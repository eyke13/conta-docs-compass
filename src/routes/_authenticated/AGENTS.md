# Screen rules (Carteira, Cobrança notices)
- Relatórios reads an aggregate-only SQL RPC (`dados_relatorios`) through the browser client, with database gestor verification and a role-verified route gate; it never opens months or mutates operational rows. Company demands, bank/card items and monthly reconciliation progress stay distinct, and XLSX exports share the same pure calculations as the screen. Why: accurate managerial totals without granting reporting access to other profiles.

- Carteiras: the responsible operator lives on `demandas.operador_id`, carried to new months; new companies are auto-assigned (talent's operator, else lightest active). Changes happen only in Carteira de Operadores (transfer/redistribute by talent group, updating the current and later competências). Why: assignment stays fixed and talents never split.
- Operador `setor` gates Cobrança assignment: Simples → SIMPLES cell, Real/Presumido → REAL_PRESUMIDO cell, per unit (padrinho within cell, see root AGENTS.md); units with no compatible operator are left unassigned and reported, never silently mis-assigned. Why: sector-based portfolios.
- Carteira de Operadores has two independent cells: BANCO | CARTÕES (one unit per empresa, weight = bancos + cartões, same operador on both `demandas` tipos, no setor lock) and COBRANÇA (`cobrancas.operador_id`, unit = padrinho within cell, opened by `abrir_cobranca()`, setor lock by regime). Prioridade never affects distribution. The top-bar Banco/Cartão switch shows only on Controle. Why: operational cells requested by the user; setor rule applies to Cobrança only.
- "Tem Otimizza?" is `empresas.tem_otimizza` (permanent, edited in Peculiaridades, shown as a notice in Cobrança). Why: company-level info, not per competência.
- Carteira regime filter and regime-scoped redistribution apply per empresa: talent groups are rebuilt from only the empresas of the chosen regime. Why: one talento can hold empresas of several regimes.
- Cobrança carteira: load = companies (weight 1); redistribution runs per cell, defaults to "minimum moves" toward the cell target (companies ÷ participants), always with a preview (src/lib/carteiraCobranca.ts); same padrinho may differ across cells; companies without regime are never auto-assigned. Why: fair loads when the team changes.

- Companies with peculiaridades show `AlertaPeculiaridade` (src/components/alertaPeculiaridade.tsx; pulsing amber icon with count, static under prefers-reduced-motion) next to the company name on Cobrança and Carteira, in every competência, never dismissible; click opens a read-only side panel. The responsible operador's row gets `DESTAQUE_PEC`. Matching is by chaveNome through `peculiaridades_por_empresa()`; each screen calls `usePeculiaridadesRealtime()` once. Why: critical company info must be seen by whoever works it.
- The sidebar menu is one map per role (`MENU_POR_PAPEL` in route.tsx): top items, then labeled groups sorted alphabetically inside each group. Menu order never changes permissions. Why: each profile is led to the screens it uses.
- Cobrança's Recebido tab has a date filter on `movimentado_em` (America/Sao_Paulo day boundaries, independent of the selected competência, kept in the URL as recebidoDe/recebidoAte); the status cards always show the competência totals. Why: the team checks what was received on a given day or period.
- Economic groups come from `grupos`/`grupo_empresas`, linked by company code (leading number of empresas.nome, `codigo_empresa()`), imported by the gestor from a curated CSV with mandatory preview (`importar_grupos()`, spelling variants merged by chaveNome); `ignorar` and manual edits in Cadastros → Grupos. On Controle and Cobrança, same-group companies stay together inside each padrinho (block at its lowest code, src/lib/grupos.ts); `grupos_situacao()` drives badges (blue: logged operador has 2+; orange: split across operadores) and the Grupo filter (URL `grupo`). Groups never change distribution. Why: avoid several operadores contacting the same client group.
- Conciliações Financeiras never depend on the selected competência: the whole table loads, rows are never deleted. `conciliacoes.meses_conciliados` is the authoritative per-month state; `marcar_mes_conciliacao` locks the demand and checks its version before updating exactly one month, deriving completion and appending `conciliacao_alteracoes` plus `historico`. Reversing a month retains the occupied interval; only gestor's explicit `reabrir_conciliacao` frees it. Legacy finalization cannot bypass monthly progress. Read via the shared conciliações query, invalidate after saves and subscribe once to Realtime. Overlap uses advisory lock + GiST exclusion; no FK to empresas so history survives cadastro changes. Why: persistent monthly progress, consistent indicators and conflict-safe permanent history.
